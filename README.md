# 例大祭打ち上げ かんたん注文

スマートフォンから料理・飲み物を注文し、グループ担当者が取りまとめるWebアプリです。「選ぶ → 確認 → 送る」の順に進み、画面下のメニューから注文履歴や担当者の取りまとめへ移動できます。スマートフォンでの利用を中心に、読みやすい文字と押しやすい操作ボタンを使っています。

## 現在の構成

| 項目 | 構成 |
|---|---|
| 画面 | React + Vite + Cloudflare Pages |
| API | Hono + Cloudflare Workers |
| DB | Cloudflare D1 |
| ログイン | 管理者が事前登録したDiscordアカウントだけを許可するOAuth2 |
| セッション | 初回認証から最長30日。同じブラウザで自動復帰。D1にハッシュ保存、Secure・HttpOnly Cookie |
| Node.js | 22.17.0 |
| Wrangler | 4.110.0 |

権限はAPI側で`member / manager / admin`を毎回確認します。ブラウザから送られた利用者ID・role・groupは認可に使用しません。CORSは環境ごとの画面originへ完全一致で制限し、書込みAPIはCSRFトークンも確認します。

Discordの数値User ID・表示名・プロフィールはD1へ保存しません。IDはOAuth callbackと管理者の事前登録時だけ一時的に処理し、環境別Secretで作った復元不能なHMAC（照合値）だけを保存します。未登録アカウントはログインできません。管理者は1アカウントだけで、宴会コースは管理者だけが閲覧・代理追加できます。代理追加された注文は、利用者の注文履歴にその旨を表示します。

## ローカル確認

画面を操作するだけなら、[ローカルのテスト画面](docs/LOCAL_DEMO.md)を使えます。`frontend`で`npm run demo`を実行し、`http://127.0.0.1:5174/__demo?role=admin`を開いてください。Excel一括追加・注文・ログイン画面を架空データで試せます。

```powershell
cd api
npm ci
npm run db:migrate:local
npm test
npm run typecheck
npm run dry-run

cd ..\frontend
npm ci
npm test
npm run lint
npm run build
```

Discord OAuthをローカルで確認する場合だけ、`api/.dev.vars.example`を`api/.dev.vars`へコピーし、ローカル用Discord Applicationの値を入れます。秘密値をGitへ追加しないでください。

## メンバーのExcel一括登録

管理画面の「参加者」から空のExcelテンプレートをダウンロードし、「参加者名・DiscordユーザーID・グループ・権限」の4列を入力します。最大100人で、人ごとにグループと権限を指定できます。ファイル選択後に内容を確認し、「この○人をまとめて追加」で登録します。従来の名前・IDの直接入力も使えます。

今回の席名は「クラシック席」「ニュークラシック席」です。Excelの選択肢と管理画面は同じ席名を使います。登録済みの管理者は一括追加せず、参加者一覧から必要な所属だけを変更します。

DiscordユーザーIDは文字列で入力してください。入力不備が1件でもあれば全員の登録を止め、Excelの行番号を表示します。詳しい入力方法とエラー時の操作は[管理者向けデータ操作](docs/ADMIN_DATA_OPERATIONS.md)を参照してください。配布ファイルは`frontend/public/templates/member-import.xlsx`、再生成用スクリプトは`scripts/build-member-import-template.mjs`です。再生成にはCodexのArtifact Toolを含むランタイムが必要で、通常のアプリ運用・ビルドでは実行不要です。

## 管理者の取りまとめと通知

管理者は「取りまとめ」と「会計」で全グループを扱えます。取りまとめは席で絞り込め、同じ料理でも席が違う注文は分けて表示します。担当者の操作範囲は自分のグループです。

管理者・担当者にはアプリ内の新着通知があります。さらに端末ごとに通知を許可すると、アプリを閉じた状態でもWeb Pushで新着を受け取れます。公開環境への追加migrationと新しい通知鍵の設定が必要です。設定前は画面に「プッシュ通知は準備中です」と表示します。通知に参加者名や注文内容は含めません。設定手順と端末の条件は[通知の説明](docs/PUSH_NOTIFICATIONS.md)を参照してください。

管理画面の「安全な操作」には「注文履歴だけを削除」があります。全員分の注文と注文合計を消し、参加者・グループ・権限・ログイン状態・メニュー・操作履歴を保持します。直近5分以内の本人確認、復元地点の記録確認、確認文の入力が必要です。機能の公開だけで既存の注文を削除することはありません。

## 現在停止している機能

- 利用者本人が送った注文の取消UI（管理者が事前追加した注文の訂正だけ利用可）
- 参加者の物理削除

参加者の「利用停止」は、ログイン許可とsessionを無効にして一覧から外す安全な操作です。参加者データを物理削除せず、過去の注文・会計・操作履歴は残します。

管理画面の「開催データをリセット」は、全注文と管理者以外の参加者データを初期化します。唯一の管理者、メニュー、操作履歴、migration情報は消しません。ただし、削除された参加者・担当者と過去の操作履歴との紐づけは解除されます。実行には直近5分以内の管理者ログイン、削除件数の確認、D1復元地点の記録確認、確認文の入力が必要です。詳しい範囲と手順は[管理者向けデータ操作](docs/ADMIN_DATA_OPERATIONS.md)を参照してください。

反応しないボタンや未完成の通信は表示していません。取消用のDB列は将来の監査付き実装に備えて残しています。

## 今回の会場への対応

ログイン前後の会場案内から「チバちゃん秋葉原電気街口店」の住所・階数・地図・公式案内を確認できます。開催日は2026年10月4日（日）、単品注文でコース・飲み放題は利用しません。開始時刻・集合方法・会費や精算方法は未定として、推測で設定しません。既存の宴会コース管理機能は今回の利用条件を示すものではなく、今回のメニュー準備は単品を対象とします。

会計は担当者が確認中の注文を含む「注文合計（目安）」です。席料や深夜料金は自動計算せず、予約条件と店舗伝票を照合します。通信結果が不明な注文は内容を固定して同じ識別子で再確認できます。アプリ内の画面切替ではカートを保持しますが、ページ再読み込み・ログアウト・セッション失効後の復元には対応していません。
