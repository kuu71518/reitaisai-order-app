# 管理者向け 参加者登録・利用停止・注文履歴削除・開催データ初期化

版: v1.7
更新日: 2026-10-02（JST）

## できること

管理画面では、次のデータ操作を行えます。

1. 参加者を1人ずつ追加
2. Excelファイル、または参加者名とDiscord User IDの直接入力から最大100人をまとめて追加
3. 参加者の利用停止、または次回開催へ向けた開催データの初期化
4. 参加者やメニューを残したまま、注文履歴だけを全員分まとめて削除
5. 主任の割当と、全グループの会計・未注文参加者を含む個別金額の確認
6. 理由と対象を確認した注文取消（伝達済みは店舗への取消確認も必須）
7. 管理者・主任による現金受領状況の記録と解除

2026-10-02の追加仕様は検証環境向けです。この文書の更新だけでは公開完了を意味しません。[今回の仕様と未確認事項](STAGING_IMPROVEMENTS.md)も参照してください。

Discord User IDは、追加が成功するまで、この画面の入力・読取結果としてブラウザのメモリ内に一時保持します。APIで照合用HMACへ変換した後に破棄し、D1、操作履歴、ブラウザの保存領域へIDそのものを保存しません。入力や読取結果はページを閉じたり再読み込みしたりすると復元できません。

## 参加者をまとめて追加する

「参加者をまとめて追加」から入力方法を選びます。どちらも最大100人で、確認画面ではDiscord User IDの末尾4桁だけを表示します。登録するのは「この○人をまとめて追加」を押した時点です。

### Excelファイルから追加する

1. 「Excelファイルから」を選び、「Excelテンプレートをダウンロード」で「メンバー追加リスト.xlsx」を保存する。
2. Excelで開き、「メンバー追加」シートの2〜101行目へ1人につき1行入力する。1行目の見出しや列順は変更しない。
3. 次の4列を全員分入力し、`.xlsx`形式・1MB以下で保存する。グループと権限は人ごとに指定できる。

   | 列 | 見出し | 入力する内容 |
   |---|---|---|
   | A | 参加者名 | 1〜80文字。改行やタブを含めない。 |
   | B | DiscordユーザーID | Discordの「ユーザーIDをコピー」で取得した16〜22桁の数字を、文字列として貼り付ける。 |
   | C | グループ | 「クラシック席」「ニュークラシック席」をセルの選択肢から選ぶ。 |
   | D | 権限 | 日本語で「一般参加者」「担当者」「主任」のいずれか。管理者は指定できない。 |

4. 管理画面の「入力済みのExcelファイル」で保存したファイルを選ぶ。この操作ではブラウザ内で読取り・検証だけを行い、ファイルや参加者情報を登録APIへ送信しない。
5. 「Excel ○行目」の表示で、名前・ID末尾4桁・グループ・権限を確認する。間違いがある場合は「入力に戻る」を押し、Excelを修正して保存したうえでファイルを選び直す。
6. 「この○人をまとめて追加」を押し、追加完了と参加者一覧への反映を確認する。

今回の2つの席名は、参加者をまだ登録していなくても選択できます。既存データに別のグループがある場合も、管理画面ではその名称を引き続き選択できます。グループが未確定の行は登録を保留し、席名の確定後に入力してください。登録済みの管理者は追加リストへ重ねて記入せず、必要な所属変更を参加者一覧の「編集」で行います。

**Discord User IDを数値として保存しないでください。** Excelでは長い数値の末尾が丸められるため、数値セルは取込みを止めます。テンプレートのB列は文字列形式です。別の表から貼り付ける際も文字列形式を保ってください。一度数値に変換されたIDは、セルの表示形式を文字列へ変えるだけでは元に戻りません。文字列形式にしたセルへ、Discordから取得し直したIDを貼り付けてください。

完全な空行は行単位で読み飛ばします。4列の一部だけが空欄の行、入力内で重複したID、不正なID、登録可能な一覧にないグループ、指定外の権限が1件でもあれば全員の取込みを止め、修正が必要なExcelの行番号を表示します。102行目以降やE列以降の入力を黙って切り捨てることはありません。数式・結合セル・旧形式の`.xls`・CSV・マクロ付きの`.xlsm`・パスワード保護されたブックは使用せず、必要に応じて新しいテンプレートへ値だけを貼り付けてください。

読み取る参加者情報は「メンバー追加」シートだけです。「使い方」など別シートの記載は登録しません。成功後はアプリ内のファイル参照と読取結果を解除します。元のExcelファイルを書き換えたり削除したりせず、コピーの作成・自動保存も行いません。入力済みExcelファイルは利用者の保存先に残るため、参加者情報として管理してください。

### 名前とIDを直接入力して追加する

1. 「名前とIDを直接入力」を選ぶ。
2. 「参加者名」へ、Aさん、Bさん、Cさんのように1人ずつ改行して入力する。見出しは入れない。
3. 「DiscordユーザーID」へ、同じ人の順番で1人ずつ改行して入力する。
4. 全員に適用するグループと権限を選ぶ。グループや権限が違う人は分けて追加する。
5. 2か所の人数が同じことを確認し、「名前とIDの組み合わせを確認」を押す。
6. 「1人目」のように表示される名前とID末尾4桁の組み合わせを確認する。
7. 「この○人をまとめて追加」を押す。

カンマ、空白、タブ、見出し行で区切る必要はありません。必ず1人ごとに改行してください。名前とDiscord User IDの先頭・途中に空行がある場合や、2か所の人数が違う場合は、別人のIDを結び付けないため追加を止めます。

権限は`一般参加者`・`担当者`・`主任`です。標準は`一般参加者`で、管理者は一括追加できません。主任は全グループの取りまとめ・伝達済み操作・通知と全参加者の会計を扱います。参加者・メニューの管理は管理者だけです。[役割と操作範囲](ROLE_PERMISSIONS.md)を参照してください。

### 追加時にエラーが出た場合

どちらの入力方法でも、1人でも入力不備または登録済みDiscordアカウントがあれば、登録APIは全員を追加せずに止まります。登録済みアカウントとの重複は送信時に確認され、Excelでは元の行番号、直接入力では何人目かを表示します。該当する入力を修正・除外し、もう一度内容を確認して追加してください。

通信エラーの場合は、サーバー側の登録が完了している可能性があります。「最新情報に更新」で参加者一覧を確認してください。同じIDで再送した場合も重複を検出して追加を止めます。追加完了後に一覧の更新だけが失敗した場合は、追加完了の案内を確認し、再登録せずに「最新情報に更新」を押してください。

## 主任と会計を確認する

主任は「会計」から、全グループの合計、グループ別合計、参加者別金額を確認できます。未注文の有効な参加者も0円で表示します。利用停止済みでも取消前の注文金額が残る参加者は会計に残します。同名の参加者も利用者IDで区別し、所属グループを表示します。

金額は確認中・伝達済みの注文分で、取消済みは除外します。「＋テーブルチャージ495円（税込）」は注意書きで、表示合計へ自動加算しません。最終支払額は店舗の伝票と照合してください。

管理者と主任は、会計の参加者ごとに現金受領済みを記録・解除できます。担当者は担当グループの注文合計だけを確認し、個人別金額・受領状況は閲覧しません。記録するのは受領状況と、その時点に確認した注文合計です。実際に受け取った現金額や495円のチャージを計算・保存する機能ではありません。

受領後に注文や取消で合計が変わった場合は注意を表示します。現金の追加受取・返金などを確認してから、最新金額を確認済みとして受領記録を更新してください。確認中に合計や別担当者の記録が変わった場合は409で止め、最新情報から確認し直します。同じ操作の結果が不明なときは同じ内容で再確認し、別の担当者による新しい記録を上書きしません。

## 注文を取り消す

- 確認中（`pending`）：注文した本人、主任、管理者が取消可能です。主任は全グループの未伝達注文を取り消せ、担当者は自分の注文だけを取り消せます。
- 伝達済み（`ordered`）：管理者だけが、店員へ連絡して取消可能なことを確認してから操作します。
- 取消済み：注文履歴と監査記録を保持し、会計の合計から除外します。商品や参加者を削除する操作ではありません。

本人は「注文履歴」、主任・管理者は「取りまとめ」の商品内訳、管理者は管理画面の注文一覧から「注文を取り消す」を押します。注文者・グループ・商品・サイズ・個数を確認し、200文字以内の取消理由を入力してください。伝達済みの場合は、店舗への取消確認欄も選びます。アプリの操作で店舗へ連絡が届くことはありません。

確認後に数量・伝達状態・所属が変わった場合は409（内容変更）で止まります。閉じて最新の一覧を確認してからやり直してください。通信結果が不明な場合は、入力内容を固定した「同じ内容で再確認」を使います。取消済みへの再送は二重処理や二重監査を行いません。再注文する前に、注文履歴と店舗への伝達状況を確認します。

## 参加者の利用を停止する

参加者カードの「この参加者の利用を停止」を押し、影響を確認してから「利用を停止する」を押します。

- 参加者一覧から外れる。
- Discordのログイン許可を消す。
- 現在ログイン中の端末をログアウトさせる。
- 過去の注文、会計、操作履歴は残す。
- 唯一の管理者は利用停止できない。

誤って停止した場合は、履歴を消さずに参加者を登録し直せます。本人確認済みのDiscord User IDをもう一度登録してください。

## 注文履歴だけを削除する

「管理」→「安全な操作」→「注文履歴だけを削除」から実行します。管理者専用です。

- 削除対象は全員分の確認中・伝達済み・取消済みの注文と、各端末に保存した通知受信履歴・未読数です。会計の注文合計も0円になります。注文が0件でも通知履歴だけを削除できます。
- 参加者、所属グループ、権限、ログイン許可、ログイン状態、メニュー、既存の操作履歴、通知登録、音と振動の設定、現金受領記録は保持します。受領時の注文合計と削除後の合計が異なる場合は、会計に変更注意が表示されます。
- 削除を実行した管理者と件数を操作履歴に追加します。
- 遅れて届いた再送から注文を復活させないため、利用者ID・注文の送信識別子・削除時刻だけを内部に保持します。商品名・価格・数量はこの記録に含めません。
- 店員への注文取消や精算の取消にはなりません。画面からの取消・元に戻す操作はありません。
- 管理者の端末は削除成功後すぐ、他の開いている端末は次の注文取得時、閉じている・通信できない端末は次に認証済みで接続したときに通知履歴を消します。同じブラウザに保存した別アカウント・別役割の履歴も対象です。削除後に受け取った新着は引き続き記録します。
- 通知履歴は端末内の記録で、D1復元では戻りません。OSの通知センターに配信済みの通知を全端末から遠隔削除する操作ではありません。

実行前に注文受付を止め、D1のTime Travel復元地点とJST時刻を非公開のrelease記録へ保存してください。管理者がDiscordで本人確認してから5分以内に、表示件数と保持するデータを確認し、復元地点の記録済み欄を選択して「注文履歴だけを削除」と入力します。最後に件数入りの削除ボタンを押します。

確認後に注文が1件でも追加・編集・削除された場合や、別の履歴削除が完了した場合は、全体を削除せず止まります。最新件数を読み込み、最初から確認してください。注文の削除・通知削除の共有記録・操作履歴の追加は一括で成功または失敗します。通知削除の共有記録は既存の操作履歴を使い、追加migrationは不要です。注文0件で同じ削除要求が重複して届いても、新たな通知削除は実行しません。通信が途切れた場合はすでに削除済みの可能性があるため、再送する前に最新件数と操作履歴を確認します。再送が削除後の新規注文や新着通知を消すことはありません。

実行後は注文0件、会計0円、各端末の通知履歴・未読0件（新着がない場合）、参加者とメニューの件数維持、操作履歴の「注文履歴だけを削除」を確認します。復元が必要な場合は受付を止めたまま[公開手順](DEPLOYMENT.md)に従ってD1を復元します。D1全体の復元では復元地点以降の変更も戻るため、別途承認と照合が必要です。機能を公開することと、実際に本番の履歴を削除することは別の操作です。

## 開催データを初期化する

この操作は次回開催の準備用です。「安全な操作」の「参加者も消す『開催データのリセット』」を開きます。D1全体を消す操作ではありません。

削除するもの:

- 全注文と取消記録
- 管理者分を含む全員の現金受領記録
- 管理者以外の参加者データ
- 現在操作中の管理者sessionを除くログインsession
- 未使用のOAuth一時状態

残すもの:

- 唯一の管理者と、そのDiscord照合用HMAC
- 現在操作中の管理者session
- メニュー
- 操作履歴と初期化の監査記録（削除した参加者・担当者との紐づけは解除され、実行者は「システム」表示になる）
- schema、migration情報、ID採番履歴

### productionでの実行条件

1. 参加者へ受付停止を案内する。
2. Cloudflare D1のTime Travel bookmarkを取得する。
3. bookmarkと取得時刻を、秘密情報を含まない非公開release記録へ保存する。
4. 管理画面からログアウトし、Discordでログインし直す。
5. 「安全な操作」で削除件数と残る件数を確認する。
6. 復元地点を記録済みの確認欄を選ぶ。
7. 指定された確認文を入力し、実行する。

画面の件数が途中で変わった場合や、ログインから5分を過ぎた場合は実行を止めます。画面を更新するか、ログインし直してください。

## 実行後の確認

- 注文が0件
- activeな管理者が1人
- メニュー件数が実行前と同じ
- 操作履歴に初期化が1件記録されている
- D1の`PRAGMA foreign_key_check`が0件
- 未登録Discordアカウントがログイン拒否される

production初回実行の前に、必ずstagingの架空データで初期化と復元の両方を確認します。本番D1の初期化や復元は、ローカル実装の完了だけでは許可されません。
