# ローカルのテスト画面

2026-10-03（JST）

Windows PowerShellで、次のコマンドを実行します。

```powershell
Set-Location 'C:\Users\reiki\OneDrive\ドキュメント\博麗神社例大祭\例大祭打ち上げ\reitaisai-app\frontend'
npm.cmd run demo
```

画面: http://127.0.0.1:5174/__demo?role=admin

- 上部の「管理者」「参加者」「担当者」「主任」「ログイン前」で画面を切り替えます。主任へ直接入る場合は`http://127.0.0.1:5174/__demo?role=chief`を使います。
- 管理者の「管理」→「参加者」からExcel一括追加を試せます。「テスト用Excel（2名）」は架空の参加者情報入りです。元の空テンプレートはアプリ内からダウンロードできます。
- 参加者で注文し、担当者の「取りまとめ」で担当グループの注文を確認して伝達済みにできます。担当者の会計は担当グループの合計だけです。表示する商品名と価格はテスト用です。
- 管理者にも「取りまとめ」「会計」があり、全グループの注文を表示します。取りまとめはグループで絞り込めます。
- 主任は全グループの取りまとめ・伝達済み操作・新着通知と全参加者の会計を扱えます。「管理」は表示しません。会計には未注文の有効な参加者も0円で表示し、495円のテーブルチャージは注意書きだけで合計に加算しません。
- 管理者・主任は架空の参加者へ現金受領を記録・解除できます。担当者には個人別の金額・受領状況を表示しません。受領後に注文や取消を行い、注文合計が変わった注意も確認してください。
- 「ビール」で項目検索すると、商品名にその文字を含まない「テスト用キリン一番搾り（生）」の中・大が見つかります。入力途中の候補選択も試せます。
- 取りまとめは商品名ごとにサイズ別数量をまとめます。商品を開いて注文者別合計を確認してください。元の注文ごとの個数編集は主任・管理者だけに表示します。
- 確認中の注文は本人・主任・管理者、伝達済みは管理者だけが取り消せます。取消理由を入力し、伝達済みでは店舗確認欄も選びます。デモでは架空の注文だけで試し、会計からの除外・取消済みの履歴を確認してください。
- 管理者の「管理」→「安全な操作」で、参加者とメニューを保持した注文履歴削除を試せます。メモリ上の架空データだけが対象です。直近5分以内のログインが必要なため、役割を選び直して確認してください。本番では削除前の復元地点記録が必要です。
- 管理者・主任・担当者の新着通知はアプリを開いた状態で確認できます。デモには通知鍵を設定せず、外部プッシュ送信は行いません。閉じたアプリへの実配信は公開環境と実端末で別途確認が必要です。
- ベルを押すと、この端末の受信履歴と未読件数が表示されます。担当者を一度開き、参加者へ切り替えて注文し、担当者へ戻ると新着を確認できます。「注文を確認」「すべて既読にする」、ページ再読み込み後の保持を試してください。別の役割の利用者には前の人の履歴を表示しません。履歴はブラウザ内に残るため、メモリDBのリセットとは別です。
- 通知設定の「音・振動を確認」で再生と振動を要求できます。PCの結果は実スマホの音・振動や、画面ロック中の通知成功を証明しません。
- 席名は「クラシック席」「ニュークラシック席」です。初期状態は主任・未注文参加者を含む架空の6名で、従来の4名のIDは維持しています。長い商品名と複数サイズの商品も表示確認用に含めています。
- 参加者は画面下の「メニュー」「注文履歴」、担当者と主任はさらに「取りまとめ」「会計」から操作します。カートが空のときは確認バーを表示しません。
- 上部の「スマホ幅で見る」で幅390pxの画面になります。
- 「最初の状態に戻す」で、このテスト内の入力・注文を初期状態に戻します。
- 終了は起動したターミナルでCtrl+Cです。サーバー停止・再起動時にデータが消えます。

## 本番との違い

APIの登録・注文処理にはアプリの実コードを使いますが、DBはメモリ上のSQLiteです。既存のDB、参加者情報、認証設定を読み込みません。Discord OAuthの入口とcallbackはテスト専用処理に置き換えます。役割ボタンで作るログインは擬似ログインで、Discordとの実接続を検証するものではありません。

デモDBは`0007_cash_receipts.sql`までのmigrationを初期化時に適用します。これはリモートD1へのmigrationや公開の実施記録ではありません。

Cookieはテスト専用名で通常のローカルAPIと分離しています。通常APIの認証・権限・CSRF検査は通ります。HTTPのloopbackのみで起動し、同じパソコンからだけアクセスできます。外部へAPIリクエストを送信しない設定です。管理者のリセット機能もこのメモリDBだけに作用します。実際の参加者情報を入力しないでください。

`npm run build`は通常モードで、デモの画面・サンプルExcel・メモリDB用サーバーを配布しません。`--mode demo`での公開用ビルドは停止します。デモは本番利用や外部共有には使えません。
