# スマートフォンの横幅と表示密度

更新日: 2026-10-02（JST）

スマートフォンで横にスクロールしないと内容が見えない、最初の画面に情報が少ない、という改善依頼に対応します。API・DB・参加者・注文金額の計算方法は変更しません。

## 表示と操作

- 1023px以下では、画面・カード・選択欄を利用できる横幅に収めます。長い名前・サイズ・内訳は折り返し、内容を画面外へ隠す方法は使いません。
- 席名と利用者名を1行にし、会場案内・通知設定を同じ行に並べます。開くと案内全体を表示します。
- 各画面の通常の説明は、タイトル横の「説明」で開閉します。読み込み失敗や注文結果などの状態表示はそのまま表示します。
- 検索とカテゴリ選択を1行に並べ、検索候補は両方の欄にまたがる幅で表示します。商品名・項目・サイズの検索と候補の上下キー・Enter・Escape操作は維持します。
- 商品カードは左に商品名・価格・サイズ、右に追加ボタンを配置します。注文確認・履歴・取りまとめ・会計・管理画面も余白と行間を縮めます。
- 取りまとめの一覧は商品名とサイズ別個数を表示し、注文者や数量変更は商品を開くと表示します。
- 会計の人数・受取状況は2列で並べます。テーブルチャージ495円（税込）の表示は維持し、詳しい説明だけを開閉式にします。注文合計にチャージを自動加算しません。
- 下の移動バーは「取りまとめ」の表示を「まとめ」に短縮し、読み上げには「取りまとめ」と新着件数を使用します。
- スマートフォンで操作するボタンの領域は44px以上、入力欄の文字は16px以上を維持します。画面の自動文字拡大で幅が広がることも抑えます。利用者によるページの拡大操作は制限しません。

## 検証の範囲

ローカルデモの架空データでブラウザーの画面幅を変更して確認します。実参加者や本番の注文を検証データとして使いません。

- 320・360・375・390・430・768・844・1023・1024・1280px幅。844×390は横向きに相当する寸法です。
- メニュー、注文履歴、取りまとめ、会計、管理の5画面。下の移動バーやカートなど、固定配置の要素も含めて計測します。
- 長い商品名・サイズ名・大きな価格、検索候補、説明・会場・通知の展開、取りまとめの内訳、注文取消・現金確認ダイアログ。
- 主任は全グループの取りまとめ・通知・会計と現金受領操作、担当者は担当グループの合計だけの閲覧と自グループ通知、一般参加者は自分の注文操作という境界を確認すること。
- iPhone・Androidの実機、Safari固有の描画、OSの文字サイズ変更、ノッチ・端末のキーボードを含む操作は、ブラウザーの画面幅による検証とは別です。

詳細な寸法と画面画像は、Git対象外の`output/playwright/mobile-width-20261002/`へ保存します。テスト・公開記録・公開前後の参加者データの照合結果は`private-data/mobile-width-20261002/`へ保存します。参加者名・Discord照合値・セッショントークンは記録や画面画像へ出力しません。

## 公開する範囲

検証済みの同じコミットを、既存の[Cloudflare PagesのGit連携](https://developers.cloudflare.com/pages/configuration/git-integration/)でstagingからproductionへ反映します。Pagesの完了状態・対象コミット・配信されるCSSとJavaScriptを確認します。

この修正では画面だけを公開し、Workerの再公開・migration・seed・参加者の削除・注文取消・受取操作を本番で実行しません。戻す場合は修正前のPages公開版へ戻し、DBを巻き戻す必要はありません。
