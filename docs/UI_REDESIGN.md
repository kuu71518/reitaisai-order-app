# UI再設計メモ

更新日: 2026-10-02（JST）

この文書は現在の実装・検証候補を記載します。2026-10-02の改善は検証環境向けで、公開完了の記録は別です。[今回の仕様](STAGING_IMPROVEMENTS.md)を参照してください。

## 対象

- 利用の約9割を占めるスマートフォンの参加者
- スマートフォン操作に慣れていない人を含む
- 最小対応幅320px

## 操作原則

- 注文は「1 選ぶ → 2 確認 → 3 送る」の順に進める。
- 送信前に注文者・送信先・商品・サイズ・個数・合計を表示する。
- 主な操作面は44px以上、本文は16px以上を基準にする。
- ブラウザの拡大を禁止しない。
- 成功・エラー・空・読込み中を見た目と文で区別する。
- エラー時は成功表示にせず、再試行前に注文履歴を確認するよう案内する。
- festival ticketを基調とした赤・藍・金の見た目を維持し、Discord色はログインボタンだけに使う。

## ログイン

- 所属グループやDiscord名の手入力を廃止し、`Discordでログイン`の1ボタンにした。
- 管理者が本人確認済みDiscord User IDを事前登録し、登録済みアカウントだけを許可する。
- 未登録アカウントは理由を明示してログイン画面へ戻し、未知のDiscord情報を保存しない。
- IDそのもの・表示名・プロフィール・メッセージは保存せず、ログイン照合用HMACだけを保存することを明記した。
- 初回の未ログインを「session期限切れ」と誤表示しない。

## 実装済み

- Discord OAuth session復元・server logout
- member / manager / chief / admin別navigation。主任はメニュー・本人履歴・全グループ会計だけを表示
- 注文cart・最終確認・冪等送信
- 通信結果不明の商品は数量・送信識別子を維持し、同じ内容で受付を再確認
- アプリ内の画面切替でもcartを保持し、cartがある状態のページ離脱ではブラウザ標準の確認を表示
- ログイン前後の会場案内から住所・階数・地図・公式案内を表示（[今回の会場と予約条件](EVENT_VENUE.md)）
- カート追加を一時表示で通知し、1点以上あるときだけ画面下部に確認バーを固定表示
- 深夜料金の注意をJST 21:30〜翌5:59だけ注文画面へ表示（会計画面では照合漏れ防止のため常時表示）
- 自分の注文履歴
- 商品名・カテゴリの項目検索、入力途中の商品・カテゴリ候補、キーボードによる候補選択
- 管理者が追加した注文の追加元を本人履歴へ表示
- managerの自グループ注文集約・数量変更・伝達済み
- managerの自グループ注文合計（確認中を含む目安、席料・深夜料金は伝票と照合）
- adminの全グループ取りまとめ・席での絞り込み・数量変更・伝達済み・会計
- 商品名を1見出しにまとめ、サイズ別合計を表示。注文者別合計と元注文ごとの編集は商品を開いたときだけ表示
- chief / adminの全グループ・グループ別・参加者別会計。未注文の有効な参加者も0円で表示
- 金額付近に「＋テーブルチャージ495円（税込）」を表示し、注文合計へ自動加算しない
- admin / managerの新着表示と、端末の許可を得て送る固定文のWeb Push（公開環境の追加設定と実端末検証が必要）
- 参加者・メニュー・認証状態を保持する注文履歴だけの削除。確認文・復元地点記録・直近の管理者本人確認・注文変更の再検査を必須にする

- 参加者を1人ずつ、または名前とDiscord User IDの2一覧から最大100人まとめて事前登録
- 参加者の安全な利用停止（ログインを止め、注文・会計・操作履歴は保持）
- 消える件数と残る件数を先に示す、再ログイン・復元地点確認付きの開催データ初期化
- privacy cover、同じブラウザで最長30日の自動ログイン、復帰時の権限再確認、通信失敗時の再確認ボタン
- PWA更新案内

## 意図的に停止している機能

- 参加者の物理削除

未完成のボタンは置きません。取消は確認対象の変更を検出したら409で止め、最新状態を読み直して確認します。通信結果不明では理由と対象を固定した再確認だけを行い、取消済みへの再送で処理を増やしません。

## 管理者の参加者操作

- 一括追加は「名前とDiscord User IDを同じ順番で1人ずつ改行 → 全員のグループと権限を選択 → 組み合わせを確認 → 全員を追加」の順にする。見出し行や区切り文字は求めない。
- 名前とDiscord User IDの人数が違う場合や先頭・途中に空行がある場合は、別人のIDを結び付けずに止める。
- 1行でも入力エラーや登録済みDiscordアカウントがあれば、誰も追加しない。
- 確認一覧ではDiscord User IDの全文を表示せず、末尾4桁だけを表示する。
- 入力中のDiscord User IDはlocalStorageやsessionStorageへ保存しない。
- 参加者の利用停止確認では、ログインできなくなること、現在の端末もログアウトすること、過去の履歴は残ることを実行ボタンの直前に表示する。
- 画面では物理削除と誤解される「削除」を使わず、「利用停止」に統一する。唯一の管理者には「管理者は利用停止できません」と理由を表示する。
- 開催データ初期化は管理者・メニュー・操作履歴を保持し、削除した参加者と過去の操作履歴との紐づけは解除されることを明記する。実行前後の結果は画面内の読み上げ領域でも通知する。

## モバイル画面

- 1023px以下では画面下に「メニュー」「注文履歴」を配置。担当者と管理者は「取りまとめ」「会計」、主任は「会計」、管理者はさらに「管理」も選べる。
- モバイルの赤いヘッダーは固定を外して高さを抑える。下部タブも縦幅を抑えつつ48pxの操作領域を残し、ホームバー用余白を確保する。
- 所属する席を画面上部に表示。会場案内は日付と開閉ボタンにまとめ、住所や地図は開いたときに表示する。
- 検索と種類の選択をメニュー上部にまとめる。スマートフォンでは種類を選択欄にし、検索欄とともに画面上端へ追従させる。候補は入力欄の近くで選択でき、高さ480px以下の横向き画面では固定を解除する。
- 商品名は18px、価格と追加ボタンは同じ行に配置。主な操作は48px以上、補助操作は44px以上を基本とする。
- カート確認・送信を画面下部へ配置。送信中は画面切替を止め、二重送信防止と結果不明時の再確認を維持する。
- 画面切替時は内容の先頭へスクロールし、キーボードのフォーカスも本文へ移す。カートはアプリ内の画面切替で保持する。
- ログアウトと担当者の伝達済み操作はアプリ内の確認画面を使う。「戻る」を最初に選択し、Escで戻れる。伝達済みにする対象は確認を開いた時点の注文に固定し、その後の新着注文は待ち一覧へ残す。
- 取消確認では注文者・席・商品・サイズ・個数を再表示し、200文字以内の理由を必須にする。伝達済みは店舗確認欄も選ばせ、取消中は関連操作を止める。取消済みを履歴から消さず、会計だけから除外する。
- 現金受領は管理者・主任だけが記録・解除し、担当者は同グループの状況を閲覧する。受領時の注文合計と現在の合計が変わった場合に注意を表示し、追加注文や取消を見落とさないようにする。
- 確定した席名「クラシック席」「ニュークラシック席」は参加者登録前から選べる。Excelテンプレートも同じ選択肢を使う。個人ごとの割当情報は公開コードへ含めない。

操作面の大きさは[W3Cのターゲットサイズ解説](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)、画面端の余白は[MDNのenv()資料](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/env)を参照した。viewport-fit=coverとsafe-area-insetでノッチやホームバーの余白を確保し、拡大操作は許可する（資料確認: 2026-10-01）。

## ローカル確認

```powershell
cd frontend
npm test
npm run lint
npm run build
```

時刻境界・メニュー表示権限・主要ロジックは自動テストします。2026-10-01のローカル確認では、frontendの37テスト・Lint・配布用ビルドが成功しました。PWAのビルド依存に由来するinlineDynamicImportsの非推奨警告は残ります。

ブラウザーの架空データでは、320〜1280pxのメニュー、検索・空の結果・サイズ選択、履歴を往復した際のカート保持、個数変更、注文の連続クリック、ログアウトの確認とEsc操作、担当者の個数保存・未保存時の伝達防止・確認後に届いた注文の保留、Excel2名の一括追加を確認しました。390px幅の最初の商品位置は画面上端から約762pxから456pxになり、320px幅の横方向のはみ出しも修正しました。

これはローカルのメモリDBと擬似ログインによる検証です。実Discord、リモートD1、公開環境、実機のiPhone Safari・Android Chromeは未検証です。通信不安定時の再送判定は自動テストで確認し、今回のブラウザー検証では通信断を注入していません。実機ではキーボード表示中、ノッチ・ホームバー、横向き、PWA更新も確認します。

管理画面の既存の所属変更では、ブラウザー標準の確認が開く操作で検証ツールが応答待ちになり、保存ボタンからの完了確認はできませんでした。長い席名の表示確認には、ローカルAPIで架空データの所属だけを変更しています。検証終了時に架空データを初期4名・注文0件へ戻して確認し、ローカルサーバーを停止しました。
